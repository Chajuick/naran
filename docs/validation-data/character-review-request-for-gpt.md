너는 심리측정 전문가이자 게임 보상 설계(gamification) 전문가 두 역할로 아래 설계를 검토해줘.

배경: "나란"은 가치관(자체 개발)·성격(OEJTS, MBTI 형식)·애착(ECR-R)·기질(IPIP TCI 대응) 4검사를 모아 나를 프로필로 정리하는 서버 없는 웹앱이다. 원칙: 검사는 우열을 평가하지 않는다, 응답 원본은 기기 밖으로 나가지 않는다, 결과 문장은 장점과 한계를 함께 말한다.
이번에 "검사 결과에 따라 분위기 태그가 붙은 픽셀 아트 옷·배경을 3개 중 1개 받는(주 1회)" 캐릭터 꾸미기를 추가하려 한다. 설계 초안 전문은 아래와 같다.

요청:
1. 10절 Q1~Q6 각각에 대해 판단(유지/수정/삭제)과 이유, 수정안.
2. 측정 오염 위험(사회적 바람직성, 아이템을 노린 응답, 재검사 유도)을 0~10으로 평가하고 가장 큰 구멍 1~3개.
3. 분위기 태그 8종과 매핑에서 특정 유형이 불리하거나 낙인처럼 읽히는 곳, 대안 태그명.
4. 보상 구조(검사 첫 완료 4회 + 주간 1회, 만료·연속출석 없음)가 재방문 동기로 충분한지, 다크패턴 요소가 있는지.
5. 반드시 고쳐야 할 것 / 고치면 좋은 것 / 그대로 둘 것 으로 정리하고, 마지막에 이 설계로 구현해도 되는지 한 줄 결론.

# 09. 내 캐릭터 — 나를 꾸며가는 픽셀 캐릭터 (설계 초안 v0.1)

> 상태: 설계 초안. GPT 검토 → 확정 → 구현. 코드 없음.
> 사용자 요청 (2026-10-02): "나를 꾸며가는 앱 답게, 캐릭터를 고르고 모자/헤어/망토/상의/하의/신발/한벌옷을 입히고,
> 검사 결과에 따라 태그 달린 아이템 3개 중 하나를 받게(쿨타임 일주일). 결과 공유 카드도 내 캐릭터 프로필로."
> 화풍: **픽셀 아트** (사용자 선택). 진행: 설계 문서부터.

## 1. 왜 하는가

| 목적 | 어떻게 |
|---|---|
| 나란의 뜻("나를 채워간다")을 눈에 보이게 | 검사가 쌓일수록 캐릭터가 꾸며진다 |
| 다시 올 이유 | 일주일에 한 번 선물 — 회차 단위(7일 = 1회차, docs/08)와 맞춘다 |
| 기록 유실 방지 | iOS 사파리는 7일 미방문 시 저장소를 지울 수 있다. 주 1회 방문 + "캐릭터가 사라져요"는 설치·백업 동기가 된다 |
| 퍼지는 공유 카드 | 글자("INFP · 안정형") 대신 내 캐릭터 한 장 |

## 2. 넘지 말아야 할 선 (측정을 지키는 규칙)

나란은 검사 앱이 먼저다. 꾸미기가 측정을 오염시키면 안 된다.

1. **답을 아이템으로 거래하지 않는다.** 어떤 답이 어떤 아이템을 주는지 공개하지 않는다. 아이템에는 "어울리는 분위기"만 보이고, 어떤 응답에서 왔는지는 보이지 않는다.
2. **모든 결과가 같은 값어치를 받는다.** 분위기 태그마다 부위별 아이템 수가 같다. 희귀도·등급 없음. 특정 유형만 화려한 옷을 받으면 "더 좋은 성격"이라는 메시지가 된다 (CLAUDE.md: 우열 평가 금지).
3. **재검사에 보상하지 않는다.** 보상은 "검사를 처음 끝냈을 때"와 "주간 선물"뿐. 매주 재검사를 유도하면 문항 학습으로 결과가 흐려진다. 재검사는 태그 가중치만 바꾼다.
4. **세 개 중 하나는 늘 와일드카드.** 프로필과 무관한 분위기 1개를 섞어 칸에 가두지 않고, 답을 맞춰 노릴 유인도 줄인다.
5. **애착 결과는 아이템에 반영하지 않는다 (초안).** 민감하고, "불안형 = ○○ 옷" 같은 연결이 낙인처럼 읽힐 수 있다. 애착 검사 완료도 선물은 주지만, 분위기는 나머지 프로필에서 정한다. → 검토 질문 Q1
6. **조급하게 만들지 않는다.** 연속 출석·만료·놓치면 사라지는 선물 없음. 받지 않은 선물은 그대로 기다린다 (단, 쌓이지 않고 하나만).

## 3. 분위기 태그 (8종)

아이템과 프로필을 잇는 중간 언어. 성격 설명이 아니라 **옷의 분위기**다.

| 태그 | 옷 느낌 | 프로필에서 오는 곳 |
|---|---|---|
| 단정 | 셔츠·정장·깔끔한 선 | 가치관 원칙형, 수식어 단단한, MBTI J |
| 든든 | 튼튼한 작업복·코트 | 가치관 보호형, MBTI S, 기질 인내력 높음 |
| 다정 | 파스텔·리본·둥근 선 | 가치관 포용형, 수식어 따뜻한, 기질 사회적 민감성 높음 |
| 포근 | 니트·담요·털모자 | 가치관 돌봄형, 수식어 포근한, 기질 위험 회피 높음 |
| 고요 | 짙은 남색·밤하늘 | 수식어 차분한, MBTI I |
| 경쾌 | 원색·스포츠웨어 | MBTI E |
| 몽상 | 별·망토·판타지 | MBTI N |
| 탐험 | 모험복·배낭·지도 | MBTI P, 기질 자극 추구 높음 |

- 가치관 **조율형**은 특정 태그 대신 모든 태그에 고르게 가중치(균형 그 자체를 반영).
- MBTI·기질은 **뚜렷한 쪽(60% 이상)만** 반영. 50~59%는 반영 안 함.
- 각 태그가 프로필에서 오는 경로 수를 비슷하게 맞춘다 (현재 2~3개). 구현 시 시뮬레이션으로 태그 분포가 한쪽에 몰리지 않는지 확인 (제3세트 28명 픽스처 재사용).

**가중치**: 가치관 대표 유형 3, 수식어 2, MBTI 각 1, 기질 각 1. 합산해 상위 태그를 고른다.

## 4. 캐릭터와 부위

### 캐릭터 고르기 (처음 한 번, 언제든 바꿀 수 있음)
- 피부색 5종 · 표정 3종 · 시작 머리 3종 중 선택. 성별 구분 없는 몸 하나.
- 시작 옷 무료 지급: 상의 2 · 하의 2 · 배경 1.

### 부위 (겹치는 순서, 아래가 먼저)
1. 배경
2. 망토(뒤)
3. 몸 (피부색·표정)
4. 신발
5. 하의
6. 상의 / **한벌옷** (한벌옷을 입으면 상의·하의 칸이 비워진다)
7. 망토(앞, 목 부분)
8. 머리
9. 모자 (쓰면 머리 윗부분을 가린다 — 머리마다 '모자 아래' 모양을 따로 두지 않고, 모자 영역 픽셀만 가림)

### 단계
- **1단계 (첫 출시)**: 머리 · 상의 · 하의 · 한벌옷 · 배경
- **2단계**: 모자 · 망토 · 신발
- 데이터 구조는 처음부터 7부위 + 배경을 다 받는다.

### 아이템 수 (1단계)
태그 8 × 부위(머리·상의·하의·한벌옷·배경 중 4개를 태그마다 고르게) = **태그당 4개, 32개** + 시작 아이템 8개.
→ 처음 4개 검사 완료 선물 + 주 1회로 약 7개월 분량. 이후 시즌마다 추가.

## 5. 픽셀 아트 규격

- 캔버스 **32 × 40 px** (캐릭터), 배경 **48 × 48 px**. 화면에서는 정수배 확대(×4~×8), `image-rendering: pixelated`.
- 아이템은 **데이터 파일**로 (`src/data/avatar/items.ts`): 팔레트 + 문자 행 배열. 코드에 그림을 넣지 않는다 (CLAUDE.md: 데이터 분리).
  ```ts
  { id: 'top-knit-cream', slot: 'top', name: '크림 니트', tags: ['포근'],
    palette: { a: '#f3e6d0', b: '#d9c4a3' },
    rows: ['....aaaa....', '...aabbaa...', ...], at: [10, 18] }
  ```
- 렌더: SVG `<rect>` 묶음 (작은 크기라 충분, 공유 카드는 canvas로 같은 데이터를 그림).
- 몸 기준선(어깨·허리·발 위치)을 고정해 모든 옷이 같은 자리에 맞도록 한다. 기준선은 문서 부록에 픽셀 좌표로 명시.
- 그림은 Claude가 데이터로 직접 그린다. 사람이 그린 그림을 쓸 경우에도 같은 형식으로 변환.

## 6. 선물 흐름

### 언제 받나
| 계기 | 횟수 | 비고 |
|---|---|---|
| 각 검사를 **처음** 끝냈을 때 | 최대 4번 | 애착 포함. 재검사는 선물 없음 |
| **주간 선물** | 마지막 주간 선물 후 7일 지나면 1번 | 안 받으면 기다림. 쌓이지 않음 |

### 무엇을 받나 — 세 개 중 하나
1. 프로필 상위 1번 태그에서 아직 없는 아이템 1개
2. 상위 2번 태그에서 1개 (1과 다른 부위)
3. **와일드카드**: 상위 2개가 아닌 태그에서 무작위 1개
- 세 개는 **만들어지는 순간 저장**한다 (새로고침해서 다시 뽑기 불가).
- 고르지 않은 둘은 사라지지 않고 다음 후보로 돌아갈 수 있다.
- 해당 태그에 남은 아이템이 없으면 다음 태그로 넘어간다. 전부 모으면 "다 모았어요" + 새 시즌 안내.

### 주간 선물의 "이번 주의 나" (선택)
선물 상자를 열 때 한 줄 메모를 남길 수 있다 ("요즘 나는 ___"). 채점하지 않고, 기록 탭 회차 옆에 보인다. 건너뛰어도 선물은 받는다.

## 7. 화면

- **나 탭 머리**: 지금의 네 조각 원(Pieces) 자리에 캐릭터. 네 조각은 캐릭터 발밑 받침 또는 둘레 고리로 유지 — "검사가 캐릭터를 채운다"가 보이게.
- **옷장** (`/closet`, 캐릭터를 누르면): 부위 탭 · 가진 아이템 격자 · 입혀보기 즉시 반영 · 캐릭터 다시 고르기.
- **선물 상자**: 받을 선물이 있으면 나 탭에 상자 카드 → 열면 세 개가 카드로 뒤집히는 애니메이션 → 하나 고르기 → 바로 입혀보기.
- 탭은 늘리지 않는다 (나/검사/기록/분석 유지).

## 8. 공유 카드

- 크기: 1080 × 1350 (피드) / 1080 × 1920 (스토리). 기기에서 canvas로 생성 → `navigator.share`(파일) 또는 저장.
- 내용: 캐릭터 + 배경, 이름(선택), 가치관 유형 이름, 한 줄 소개, `naran-kappa.vercel.app`.
- **보일 항목은 사용자가 고른다**: 가치관 유형(기본 켬) · MBTI(기본 켬) · 기질 상위(기본 끔) · **애착(기본 끔)**.
- 문항별 응답·점수 원본은 절대 넣지 않는다 (CLAUDE.md: 공유는 결과 요약만).

## 9. 저장 구조

`useStore` 에 `avatar` 추가 (localStorage `naran-v1`, persist 버전 올리고 migrate):
```ts
avatar: {
  base?: { skin: number; face: number };
  equipped: Partial<Record<Slot, string>>;   // Slot = hat|hair|cape|top|bottom|onepiece|shoes|bg
  owned: string[];
  offers: { id: string; reason: 'module' | 'weekly'; module?: ModuleKey; items: [string, string, string]; createdAt: number }[];
  claimedModules: ModuleKey[];               // 처음 완료 선물 받은 검사
  lastWeeklyAt?: number;
  notes: { at: number; text: string }[];     // 이번 주의 나
}
```
- 설정의 백업 내보내기·가져오기에 `avatar` 포함.
- 선물 생성은 순수함수 `makeOffer(profileTags, owned, rng)` + 단위 테스트 (와일드카드 규칙, 중복 없음, 태그 소진 처리).
